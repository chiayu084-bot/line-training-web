① 導購流程

30 秒快速理解
用戶從 LINE 購物出發 → 經過跳轉頁（TP）產生 ecid → 合作夥伴記錄 ecid 在 Cookie（至少24小時） → 訂單成立後即時呼叫 orderinfo → 過鑑賞期後呼叫 orderfinish → ordertime + 30 天後發送 LINE POINTS。金額要扣掉運費和優惠券，優惠券按比例攤提。

核心重點

ecid 記錄最新值：同一用戶每次跳轉都會產生不同 ecid，Cookie 有效時間至少 24 小時。
訂單成立定義：Cookie 效期內所有導購訂單皆須回拋，含購物車跨店、多次購物等情境。
金額計算：甲 1,000 + 乙 1,500 = 2,500，優惠券 300，回拋總額 2,200。甲：880，乙：1,320（優惠券按商品金額比例攤提）。

② 首次訂單回拋 API（orderinfo）

30 秒快速理解
訂單成立後即時呼叫 POST /tracking/orderinfo。金額欄位叫 product_amount（不是 product_fee）。Hash 用 ordertime 做 MD5 得到 key，再 HMAC-SHA256。付款/物流/用戶身份等欄位只有 orderinfo 能提供，一旦成功就無法更新。
欄位型別說明
site 必填int固定值 2
shopid 必填intLINE 購物核發之商城代號
authkey 必填stringLINE 購物核發之認證代碼
ecid 必填string64碼英數混合用戶識別碼
timestamp 必填intUnix timestamp
hash 必填stringHMAC-SHA256 驗證碼
orderid 必填string支援 a-z A-Z 0-9 # - _
ordertime 必填stringGMT+8，YYYY-MM-DD HH24:MI:SS
ordertotal 必填int須等於 product_amount 加總
product_amount 必填int品項總金額，優惠券須按比例攤提。不可寫成 product_fee
sub_category1 必填string第一層目錄名稱
orderinfo 金額欄位是 product_amount，orderfinish 才是 product_fee，切勿搞混。
欄位說明
payment_methodCASH/CREDITCARD/THIRDPARTY
third_paymentLINEPAY/APPLEPAY/GOOGLEPAY 等
card_brandVISA/MASTER/JCB 等，不可回傳 0
delivery_methodHOMEDELIVERY/CVS/FASTDELIVERY/INSTORE
is_new_member / is_vip / is_app1=是，0=否
invoice_number兩位大寫英文+八位數字
付款、物流、用戶身份及 custom_tag 只有 orderinfo 能提供，一旦成功就無法更新。

③ 請款訂單回拋 API（orderfinish）

30 秒快速理解
鑑賞期後（7-14天）呼叫 POST /tracking/orderfinish。金額欄位叫 product_fee（不是 product_amount）。Hash 用 feetime 做 MD5，簽名字串也不同。整筆退貨不須呼叫，部分退貨才要呼叫並扣除退貨品項。
欄位型別說明
site/shopid/authkey/ecid/timestamp/hash/orderid-同 orderinfo
ordertimestring不可與 orderinfo 的值不同
feetotal 必填int等於 product_fee 加總
feetime 必填string消費者確認完成且過鑑賞期的時間
product_fee 必填int品項實際金額。不可寫成 product_amount
orderfinish 金額欄位是 product_fee，總金額是 feetotal。與 orderinfo 的欄位名稱不同！
// Step 1: feetime 做 MD5
feetime_hashkey = md5('2018-02-16 10:05:15')

// Step 2: 簽名字串含 feetime 與 feetotal
hash = hash_hmac('sha256',
  'orderid=20180201080001&feetime=2018-02-16 10:05:15&feetotal=500×tamp=1521011477',
  feetime_hashkey)

// 結果：
9ca2cf51ca2427d336b6f0e7f27e0527846060de295550528cfce58aff1108d7

部分退貨：fee_list 只放未退貨商品，金額扣除退貨品項。

整筆退貨完全不需要呼叫 orderfinish。

④ 商品資料 Feed 規格

30 秒快速理解
三支 API：product_full（每日）提供全部商品、product_partial（每小時）提供異動商品、cate_full（每日）提供目錄。格式 JSON UTF-8。圖片更換時網址必須不同。顏色只支援 17 種定義值。

⑤ 回應訊息對照表

30 秒快速理解
API 回傳 OK 就是成功。回傳 Fail 開頭就是有錯，依據訊息修正後重送。常見的坑：product_amount 和 product_fee 名稱搞混、hash 的 orderinfo 和 orderfinish 規則不同、ordertime 第一次送出後不能改、金額加總誤差不能超過 10。
